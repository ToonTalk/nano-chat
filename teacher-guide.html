Teaching with Nano Chat

A guide for teachers. Students take a chatbot apart, or build one up from a bare language model, and see for themselves which abilities belong to the model and which to the software around it.

The idea in one paragraph

Nano Chat is a chatbot whose model is Gemini Nano, the small language model built into Chrome. Every ability the page adds around that model is a part with a switch: instructions, today's date, a calculator, web search, notes, a contents list for long conversations, and more. With every part off, students meet a bare model. With all of them on, they have a working chatbot. Under any reply, "Try again…" reruns the same message with different parts and shows the answers side by side.

What students can learn

  • A language model continues text. It has no clock, no calculator, no access to the web, and no memory of earlier chats unless software supplies them.
  • A model's fluency and confidence say nothing about whether it is right. Bare Nano states a wrong date, wrong sums and invented page contents in the same calm voice as true things.
  • A model can read only a limited amount at once. Long conversations work because software summarizes or drops the old parts.
  • Model output varies by chance, so a single trial is weak evidence. This is a natural place to practice fair testing.
  • Much of what makes a chatbot dependable is ordinary programming: a parser for arithmetic, a search request, rules of thumb.

Before the lesson

Check the computers first. This is the main practical obstacle. Not every computer can run Chrome's built-in model.
  • Browser: Chrome 148 or newer on Windows 10 or 11, macOS 13 or newer, or Linux. Ordinary Chromebooks cannot run it; a Chromebook Plus can. Phones and tablets cannot.
  • Hardware: either a graphics card with more than 4 GB of its own memory, or 16 GB of RAM and at least 4 processor cores. Many budget laptops with 8 GB of RAM will not qualify.
  • Disk and download: 22 GB of free disk space. On first use Chrome downloads the model, a few gigabytes, once for all sites. Do this before class, on each machine, on an unmetered connection.
  • Speed: on the laptop it was built on, a plain reply took 1 to 3 seconds and a searched one 7 to 9. Slower machines will take longer.
  • If machines are short: run it on one computer with a projector and let the class predict each result, or put students in groups around the machines that work.

To test a machine, open Nano Chat. If it cannot run, the page says so and lists what is needed.

The student guide walks through eight experiments the first way, then turns to the second.

A lesson outline (about 50 minutes)

  1. Predict (5 min). Ask the class what a chatbot would do if you asked it today's date, a hard sum, and what is on a web page. Collect predictions.
  2. Bare model (10 min). Students open the bare link and try experiments 1 to 3 from the student guide. Insist that they judge each answer themselves before trying again.
  3. Add parts (15 min). Experiments 4 to 6, using "Try again with it on" and opening the tool chips to see what the model was handed.
  4. Chance (5 min). Everyone runs the sum three times with the calculator off. Compare wrong answers across the room. Why are they different?
  5. Memory (10 min). Experiment 7, with the small-memory switch, as a demonstration or in pairs.
  6. Discuss (5 min). Use the questions below.

Questions for discussion

  • Which abilities did you think belonged to "the AI" that turned out to be ordinary software?
  • Bare Nano gave a date, a sum and a description of a web page it could not see. Why didn't it say "I don't know"? What changed when the Instructions part told it to say when it was unsure?
  • With web search on, the answer names its source. Does that make it right? How would you check?
  • The big commercial chatbots use far larger models. Which parts do they still need, and why?
  • A summary replaces old messages in a long conversation. What could go missing?

What to expect, honestly

  • Results vary. Chrome does not let a page fix the model's randomness. A probe that fails for most students may succeed for one. Treat that as data, and use "Run 3 times".
  • Bare Nano is better than you might expect at some things. In testing it multiplied two four-digit numbers correctly by working step by step. It reliably got percentages and powers wrong, which is why the suggested sum is a percentage.
  • The complete chatbot is still a small model. With every part on it can misread a search result or round a calculator's answer. That is worth discussing, not hiding.
  • Built for English, though Nano knows other languages. The page, its instructions to Nano and its tools are in English, and web search uses the English Wikipedia. Nano itself reads and writes other languages: in our test it answered correctly in French, Swedish and Japanese, and gave the wrong capital of Wales in Welsh. Chrome lists English, Spanish, Japanese, French and German as the languages it supports. Ask Nano which languages it knows and it will claim "hundreds" and say it is always learning. Neither claim can be trusted, which makes it a good probe.
  • Pictures and sound are not on every computer. On some, Chrome gives Nano text only, and then the paperclip offers files alone. Where they work, Nano read printed words in a picture and wrote down a clear recording correctly in testing. It has not been tried on photographs of handwriting, or on noisy rooms.
  • Chrome may change. The model and its rules belong to Chrome and are updated by Google. In November 2026 the installed model called itself "Gemma" when given no instructions.

Privacy

  • The model runs on the student's computer. Chats and notes are stored in that browser only. There are no accounts.
  • A web search sends the search words to Wikipedia. Reading a link fetches that page, through the r.jina.ai reader service when the site blocks direct reading; that can be switched off in Settings.
  • Voice input is off by default. When switched on, the page asks Chrome to recognize speech on the computer itself. Chrome's online recognition, which sends audio to Google, is a separate switch.
  • Pictures, photos and recordings are kept in the browser with their chat and are given only to Nano, on the same computer. The camera and microphone are used only when a student chooses “Take a photo” or “Record sound”, and the browser asks permission first. Remind students not to photograph or record other people without asking.
  • On a shared computer, the next student can see earlier chats and notes. Each chat and note has a delete button, and Settings, under "What this browser keeps", can delete all chats, all notes, or everything including settings and keys. Separate browser profiles also keep students apart.

The optional coach

With an API key for Claude, Gemini or ChatGPT entered in Settings, a much stronger model reviews Nano's replies. It asks the student what they think first (three quick choices, or their own words), gives a hint if they missed a problem, then explains the reply in terms of the parts and suggests an experiment. The student can talk with it about the reply, and when there are several answers it comments on each. Nano never sees what the coach says.

  • Cost: each review is charged to the key. In our test with Claude Sonnet 5.5 in November 2026, a review used about 1,700 tokens in and 750 out, around one US cent. A review that used web search read 25,000 to 37,000 tokens, several cents.
  • Pictures and recordings: the coach is given Nano's own description of them. A picture itself goes to the coach's company only if “Let the coach see pictures I attach” is ticked in Settings. Recordings are never sent.
  • Privacy: each reviewed reply goes to that company, with the student's message, the few messages before it, and what the tools found. Decide whether that suits your setting before giving students a key.
  • A coach with no key and no bill: there is a copy of Nano Chat for Gemini Canvas whose coach is Gemini, used through each student's own Google account, so nobody needs a key. Each student has to be signed in to Google with an account that is allowed to use Gemini, and the reviewed replies go to Google. Google does not document this way of working, so it may stop, and the shared copy is a snapshot that can be older than the app here. Try it on a student account before relying on it.
  • Keys: a key typed into Settings is stored in that browser unless you tick "Keep keys only until this tab is closed" beside it. Tick it on a shared machine, or do not leave a personal key there.
  • It can be wrong. Without its web search switched on, it knows nothing recent.

The lesson works without the coach. The side-by-side comparison does most of the teaching.

Going further

  • Have students invent their own probe for a part and trade probes with another group.
  • Switch off "Rules of thumb" and count how often the model picks the wrong tool by itself.
  • Switch on "Second look" and tally how often a model catches its own errors.
  • Use the Save button to keep a chat as a web page for a report.
  • Compare Nano with the first ChatGPT. Thirty examples set the answers ChatGPT gave in December 2022 beside Nano's answers to the same questions, bare and with every part on. Students can judge each set before opening the scores, which another AI gave without knowing who wrote what. It is a small sample, and the page says what it does not show.
